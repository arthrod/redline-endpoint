# Attempted Methods for Fixing Word "Unreadable Content" Warning

## Problem

When opening DOCX files generated by Docxodus/WmlComparer, Microsoft Word displays:
> "Word found unreadable content in [filename]. Do you want to recover the contents of this document?"

The document works after clicking "Yes", but the warning is undesirable.

---

## Attempt 1: Remove pt14 Namespace Only

**What we tried:**
- Remove `pt14:Unid` and `pt14:Status` attributes from all elements
- Remove `xmlns:pt14="http://powertools.codeplex.com/2011"` namespace declaration
- Remove `pt14` from `mc:Ignorable` attribute

**Code:**
```csharp
private static void CleanXmlPart(OpenXmlPart part)
{
    // Remove all pt14 attributes from all elements
    foreach (var element in xdoc.Descendants())
    {
        var pt14Attrs = element.Attributes()
            .Where(a => a.Name.Namespace == Pt14)
            .ToList();
        foreach (var attr in pt14Attrs)
            attr.Remove();
    }
    // Remove namespace declaration and mc:Ignorable entry
}
```

**Result:** ❌ Still showed warning

**Why it didn't work:** The pt14 namespace was successfully removed, but the underlying issue was in the relationships file, not the XML content.

---

## Attempt 2: Fix Relationships Using OpenXML SDK Features API

**What we tried:**
- Access the underlying `System.IO.Packaging.Package` through `IPackageFeature`
- Modify relationship IDs and paths directly

**Code:**
```csharp
var package = mainPart.OpenXmlPackage.Features.GetRequired<IPackageFeature>().Package;
```

**Result:** ❌ Build error - `IPackageFeature` is internal

**Why it didn't work:** The OpenXML SDK 3.x made `IPackageFeature` internal, so we can't access the underlying package this way.

---

## Attempt 3: Fix Relationships Using ZipArchive (Current)

**What we tried:**
- Two-pass approach:
  1. First pass: Clean pt14 namespace using OpenXML SDK
  2. Second pass: Fix relationships using `ZipArchive`
- Fix GUID-style IDs (`R76e2e2db410345d5` → `rId8`)
- Fix absolute paths (`/word/footnotes.xml` → `footnotes.xml`)

**Code:**
```csharp
private static byte[] FixRelationshipsWithZip(byte[] docBytes)
{
    using var archive = new ZipArchive(inputStream, ZipArchiveMode.Read);
    // Copy all entries, fixing .rels files along the way
    if (entry.FullName.EndsWith(".rels"))
    {
        var xdoc = XDocument.Load(entryStream);
        FixRelationshipsXml(xdoc);
        xdoc.Save(newEntryStream);
    }
}
```

**Result:** ⏳ Testing in progress

**Issues found in relationships:**
```xml
<!-- Before (broken) -->
<Relationship Id="R76e2e2db410345d5" Target="/word/footnotes.xml" ... />

<!-- After (fixed) -->
<Relationship Id="rId8" Target="footnotes.xml" ... />
```

## Root Cause Analysis

The Docxodus/WmlComparer library (based on OpenXmlPowerTools) introduces two types of issues:

### 1. PowerTools Internal Namespace (`pt14`)
- Adds `pt14:Unid` attributes for internal tracking
- Adds `pt14:Status="Deleted"` for paragraph tracking
- Declared in `mc:Ignorable` but Word still flags them

### 2. Non-Standard Relationship Format
- Uses GUID-style IDs instead of `rIdN` format
- Uses absolute paths (`/word/...`) instead of relative paths
- These are created when WmlComparer adds footnotes/endnotes parts
